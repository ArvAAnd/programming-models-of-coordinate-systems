# Лабораторна робота №1: Програмні моделі систем координат

## 1. Короткий опис роботи
Метою роботи є проектування та реалізація імутабельних моделей даних для точок у 2D та 3D просторах, реалізація механізмів конвертації між декартовою, полярною та сферичною системами координат за допомогою статичних фабричних методів, а також обчислення відстаней між точками різними математичними підходами. Фінальним етапом є експериментальний аналіз продуктивності розрахунків.

## 2. Інструкції для запуску проекту
Для запуску проекту потрібен встановлений **Python 3.10** (або вище), оскільки використовуються оптимізовані `dataclasses` з `slots=True`.
Ніяких додаткових бібліотек (крім вбудованих `math`, `time`, `random`, `statistics`) встановлювати не потрібно.

## 4. Результати аналізу продуктивності
```
--- Результати (Медіанний час у секундах) ---
2D Полярна відстань:     0.02392 с
2D Декартова відстань:   0.00949 с
3D Сферична (хорда):     0.05618 с
3D Сферична (дуга):      0.03822 с
3D Декартова відстань:   0.01163 с
```

### Аналіз та висновки:
- Для 2D: Розрахунки у декартовій системі виконуються значно швидше, ніж у полярній. Це пов'язано з тим, що декартова формула потребує лише операцій віднімання, множення та видобування кореня (math.hypot), тоді як полярна система вимагає виклику дорогих тригонометричних функцій (наприклад, math.cos).

- Для 3D: Аналогічно до 2D простору, обчислення стандартної евклідової відстані в декартових координатах є найшвидшим методом. Обчислення сферичної хорди та дуги є найповільнішими, оскільки для них потрібно кілька викликів синусів, косинусів та арккосинуса (для дуги), що суттєво навантажує процесор. Найскладнішою (і найповільнішою) виступає розрахунок дугової відстані через необхідність зворотних тригонометричних функцій (acos).

## 5. Загальний висновок
Під час виконання лабораторної роботи були закріплені навички створення імутабельних структур даних та патерну "Фабричний метод". Ключовим інсайтом стало розуміння обчислювальної вартості математичних функцій: тригонометричні перетворення (синуси, косинуси) вимагають значно більше процесорного часу в порівнянні з базовими арифметичними операціями, що критично важливо враховувати при розробці високонавантажених або ігрових рушіїв.
